# [1062C/962C][5.1.1][UK][John] Wireless Clients on Different SSIDs Cannot Communicate on the Same LAN

**Product:** VigorAP 1062C and VigorAP 962C  
**Version:** 5.1.1  
**Ticket:** Ticket needed  
**Issue:** Wireless clients on different SSIDs assigned to the same LAN cannot communicate.  

### Description

On firmware 5.1.1, wireless clients connected to different SSIDs assigned to the same LAN are unable to communicate. Clients connected to the same SSID communicate normally.

The issue occurs with both tested AP models, with DrayOS 4 and DrayOS 5 routers, and in Mesh and non-Mesh configurations.

### Devices Tested

- VigorAP 1062C running firmware 5.1.0.1 and 5.1.1
- VigorAP 962C running firmware 5.1.0.1 and 5.1.1
- Vigor 2866ax running DrayOS 4
- Vigor 2767ax running DrayOS 5

### Steps to Reproduce

1. Run a VigorAP 1062C or VigorAP 962C on firmware 5.1.1.
2. Configure multiple SSIDs assigned to the same LAN.
3. Connect wireless clients to different SSIDs.
4. Attempt communication between the clients.
5. Repeat the test with clients connected to the same SSID.
6. Repeat in Mesh and non-Mesh configurations using the Vigor 2866ax and Vigor 2767ax.

### Expected Behaviour

Wireless clients connected to different SSIDs assigned to the same LAN should be able to communicate unless client isolation or a similar isolation feature is enabled.

### Actual Behaviour

Clients connected to different SSIDs assigned to the same LAN cannot communicate. Clients connected to the same SSID communicate normally.

### Additional Information

The issue was reproduced with both AP models, both DrayOS 4 and DrayOS 5 routers, and with and without Mesh.

After downgrading the VigorAP 962C from 5.1.1 to 5.1.0.1, clients on different SSIDs assigned to the same LAN could communicate normally. Firmware 5.1.0.1 works as expected, indicating that the observed behaviour began with 5.1.1.

### Missing Information

- Ticket or reference number was not supplied.
- The configured state of client isolation or similar isolation features was not explicitly provided.

**Request:** Please confirm whether this behaviour is a limitation or a bug in firmware 5.1.1 and investigate.
